---
title: チェックモード
description: 修正表・辞書・無効の各モードを、全体またはパス単位で選びます。
---

ayame-spell は、確度の高い修正と未知語の検出を分離しています。モードが制御する
のは英単語のチェックで、日本語チェックは独立して設定します。

## 修正表モード

```toml
[check]
mode = "corrections"
```

既定のモードです。組み込み修正表または追加した修正表に載っている単語だけを
報告します。それ以外の識別子を誤字と決めつけないため、設定なしで CI に導入する
基準として適しています。

新しい誤字の見逃しより、誤検出のコストが高い場所で使います。

## 辞書モード

```toml
[check]
mode = "dictionary"

[words]
dictionaries = ["registry:en-base"]
```

修正表モードの全チェックに加え、プロジェクト辞書・ユーザー辞書・設定した辞書の
どれにもない単語を報告します。修正候補は編集距離を使って順位付けします。

レジストリ辞書は、設定で参照する前にインストールします。

```sh
ayame-spell dict add en-base python
```

文章、公開 API のドキュメント、語彙を継続管理できるプロジェクトに向いています。

## 無効モード

```toml
[check]
mode = "off"
```

英単語のチェックを無効にします。日本語チェックは引き続き動作できます。その
パスで全チェックを止める場合は、上書き設定に `japanese = false` も追加します。

## パスごとにモードを変える

```toml
[check]
mode = "corrections"

[[overrides]]
paths = ["docs/**", "*.md"]
mode = "dictionary"

[[overrides]]
paths = ["tests/fixtures/**"]
mode = "off"
japanese = false
```

上書き設定は記載順に評価し、後にある一致項目が優先されます。変更できるのは
`mode` と `japanese` だけです。辞書やルール設定は、ユーザー設定と
プロジェクト設定をマージした値を使います。

## 現実的な導入順

1. リポジトリ全体を修正表モードで始める。
2. `en-base` と技術領域に合う辞書を導入する。
3. `[[overrides]]` でドキュメントだけ辞書モードにする。
4. `words collect` と `words triage` を実行する。
5. プロジェクト辞書が安定してから、辞書モードの範囲を広げる。
