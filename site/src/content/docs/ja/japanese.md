日本語チェックは英語のチェックモードから独立しています。`[check].mode = "off"`
でも日本語表記だけ確認でき、選択したパスだけ日本語を無効にすることもできます。

## 低ノイズな既定値：一貫性

```toml
[japanese]
enabled = true
katakana-style = "consistency"
```

一貫性モードは `サーバ` と `サーバー` のどちらか一方を、それだけで正しいとは
決めません。一方の表記だけを使う文書は指摘なしです。既知の両表記が混在すると、
少数側を報告して多数側を候補にします。

既存のスタイルを保ったまま、意図しない混在だけを検出できます。一貫性の判定は
文書単位なので、別のファイルがもう一方の表記で統一されていても問題ありません。

## 長音あり・なしを指定する

スタイルガイドで方向が決まっている場合は明示します。

```toml
[japanese]
katakana-style = "long"  # サーバ → サーバー
```

または次のとおりです。

```toml
[japanese]
katakana-style = "short" # サーバー → サーバ
```

`"off"` は組み込み長音ペアの方針を無効にします。`[japanese].enabled` を
`false` にしない限り、明示した表記ゆれルールは動作します。

## 一貫性を既定にする理由

以前の日本語技術文書では、3 音以上の用語で語尾の長音符号を省略する機械的な
原則がよく使われていました。JIS Z 8301 の 2019 年改正では、この省略原則を
示す表が削除され、外来語表記は主に内閣告示の指針による形へ変わりました。
[日本規格協会の改正説明資料](https://webdesk.jsa.or.jp/pdf/dev/md_4632.pdf)
にも、この表の削除が記載されています。

実際のプロジェクトには今も両方の定着したスタイルがあり、製品名や領域用語で
意図的に違う表記を使う場合もあります。そのため ayame-spell は長音あり・なしの
一方を普遍的な誤りとせず、既定では混在だけを検出します。

## 明示的な表記ゆれ

プロジェクト固有の推奨表記はインラインマップにします。

```toml
[japanese.variants]
"インタフェース" = "インターフェース"
"ソフトウエア" = "ソフトウェア"
```

再利用するルールセットはファイルへ分けます。

```toml
[japanese]
variant-files = ["dict/product-variants.toml"]
```

```toml
# dict/product-variants.toml
[variants]
"ウエブサイト" = "ウェブサイト"
```

レジストリには、より大きなルールセットがあります。

```sh
ayame-spell dict add ja-tech-variants
```

`ja-tech-variants` は現代的な技術文書向けの小さく方針の明確なセットです。
`ja-variants` は SudachiDict 由来の広い表記ペアを収録するため、推奨側が
プロジェクトのスタイルと合うか確認してから有効にしてください。

## 全角英数

```toml
[japanese]
flag-fullwidth-alnum = true
```

`ＡＢＣ１２３` のような連続を `fullwidth-alnum` として報告し、安全な置換
`ABC123` を提示します。

## 半角カタカナ

```toml
[japanese]
flag-halfwidth-kana = true
```

`ﾃﾞｰﾀ` を `halfwidth-kana` として報告し、安全な置換 `データ` を提示します。
変換時に濁点・半濁点も合成します。

## 全角スペース

```toml
[japanese]
fullwidth-space = "code"
```

方針は次の三つです。

- `"code"`（既定）：ソースファイルの U+3000 を報告し、文章として認識する
  形式では許可。
- `"always"`：すべてのファイルで報告。
- `"never"`：報告しない。

Markdown などの文章でも全角インデントを禁止する場合は `"always"` を使います。

## パス単位で日本語を無効にする

```toml
[[overrides]]
paths = ["vendor/**", "tests/fixtures/**"]
japanese = false
```

後にある一致項目が優先です。例外的な行やファイルにはインライン
ディレクティブも使えます。
