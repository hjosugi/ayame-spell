---
title: トラブルシューティング
description: 設定検出、辞書不足、過剰な指摘、エディター起動、予期しない除外を診断します。
---

## 最初に実行するコマンド

```sh
ayame-spell --version
ayame-spell config
ayame-spell check path/to/file --format human
```

一つ目でシェルが見つけるバイナリを確認し、二つ目で設定の検出・マージ結果を確認
します。三つ目でリポジトリ全体の症状を一ファイルに絞ります。

## 設定を読み込まない

- `ayame-spell config` を実行し、`# root` と `# project config` を確認する。
- ファイル名は正確に `ayame-spell.toml` または `.ayame-spell.toml` にする。
- 最初のチェック対象から上位へ設定を探す。別プロジェクトのパスを一回の実行に
  渡すと、最初のパスが設定を決める。
- 未知のキーがあるとファイルパス付きのエラーになる。
- エディターではワークスペースルートに設定を置く。ルート検出を変更したら LSP
  クライアントを再起動する。

## レジストリ辞書が見つからない

`registry:en-base` のような項目はローカルキャッシュだけに解決します。チェック
中に自動取得はしません。

```sh
ayame-spell dict add --cache-only en-base
ayame-spell dict list
```

独自レジストリの場合は、エディターや CI が見る環境に
`AYAME_SPELL_REGISTRY` があるか確認します。チェックサム不一致なら、配信ファイル
と `index.json` が一致していません。検証を回避せず、レジストリを再生成または
修復してください。

## 辞書モードの指摘が多すぎる

1. `en-base` を導入し、設定したか確認する。
2. 技術領域に合う辞書を追加する。
3. `words collect --min-count 2` で繰り返す指摘を優先する。
4. `words triage` を実行し、プロジェクト単語をコミットする。
5. `[[overrides]]` で辞書モードを文章に限定する。

初回結果を空にするためだけに、誤字らしい語を単語リストへ追加しないでください。

## 期待した誤字を報告しない

- 修正表モードは既知の誤字だけを報告する。新しい誤字には辞書モードを試す。
- `[words].ignore`、プロジェクト単語、ユーザー単語、自分自身への修正を確認する。
- インラインディレクティブを探す。
- URL、メール、ハッシュ風の値、バックスラッシュのエスケープ、全大文字の未知語、
  短い未知語は意図的に除外する。
- 後に一致する上書きが `mode = "off"` にしていないか確認する。

## ファイルをチェックしない

- ディレクトリ走査には `.gitignore` と `[files].exclude` が適用される。
- 隠しファイルには `include-hidden = true` が必要。
- 先頭付近に NUL バイトがあるファイルはバイナリとして除外する。
- `max-file-size` による除外件数はコマンド概要に出る。
- ファイルパスを直接渡して走査の影響を切り分ける。

## エディターに診断が出ない

1. ターミナルで `ayame-spell lsp --stdio` を実行する。LSP 入力を待って無言の
   ままになるので、`Ctrl-C` で終了する。
2. エディタープロセスの `PATH` から `ayame-spell` を見つけられるか確認する。
   GUI アプリの環境はシェルと異なる場合がある。
3. クライアント別ログを確認する。`:checkhealth vim.lsp`、`hx --health`、
   Zed.log、Eglot イベント、Sublime LSP ログ、JetBrains LSP Consoles など。
4. 現在のバッファーがファイル形式・セレクター・対応付けに含まれるか確認する。
5. ワークスペースルートと設定を確認する。
6. 設定変更後にクライアントを再起動する。

大きな開いている文書は編集ごとではなく、保存時に確認します。

## コードアクションがない

クライアントが `textDocument/codeAction` を要求する必要があります。直接置換は
標準のワークスペース編集です。プロジェクト・ユーザー辞書の操作は
`workspace/executeCommand` を使うため、対応能力がないクライアントでは表示
しないか拒否する場合があります。ターミナルで `ayame-spell words add` または
`words triage` を使ってください。

## JSON 全体を一つの値として解析できない

`--format json` は JSON 配列ではなく JSON Lines です。各行を個別に解析します。

```sh
ayame-spell --format json | jq -c .
```

## `fix` の後も指摘が残る

未知語と候補が複数ある修正では正常です。手作業またはエディターのコードアクション
で確認してください。もう一度チェックすると、残った指摘だけを表示します。

## 再現可能な不具合を報告する

次を含めてください。

- `ayame-spell --version`
- 再現する最小の入力
- `ayame-spell config` から関連する最終設定
- 正確なコマンド、またはエディターとクライアントのバージョン
- 人向けまたは JSON の出力

秘密情報と非公開語彙を取り除いてから
[GitHub issue](https://github.com/ayame-editor/ayame-spell/issues)を作成してください。
