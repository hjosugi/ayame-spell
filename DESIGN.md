# ayame-spell design notes

## The gap in the market

Competitive research (2026-07) across typos, cSpell, Harper, codespell,
Vale, misspell, typos-lsp, ltex-plus, textlint, prh, and RedPen shows a
clean split:

- **Correction-table tools own CI** (typos: ~zero false positives, `-w`
  fix-all is safe) but have no dictionary sharing, no editor add-word flow,
  and miss unknown typos.
- **Dictionary tools own the editor** (cSpell: 200+ importable dictionary
  packages, rich quick fixes) but drown new projects in false positives,
  add words one at a time, and die on large files — cSpell's `checkLimit`
  silently stops checking after ~500 KB.
- **Japanese proofreading lives in a separate world** (textlint/prh,
  Node-based), and no spell checker handles it at all.

Nobody offers both modes behind one config with shared dictionaries.
That unification — plus bulk triage and honest large-file behavior — is
ayame-spell's reason to exist.

## Architecture

```
crates/
  ayame-spell-core   engine: tokenizer, corrections, FST wordlists,
                     Japanese checks, config (no I/O beyond file loads)
  ayame-spell        CLI (check/fix/words/dict/init/config) + LSP server
  xtask              registry index and shell completion generation
editors/vscode       thin LanguageClient + bulk-triage QuickPick UI
site/                GitHub Pages: landing page + dictionary registry
```

Key decisions:

- **Rust, single binary.** The LSP server is `ayame-spell lsp`, not a
  second binary — one artifact to install/bundle.
- **Tokenizer kills false positives before any dictionary runs**: URLs,
  e-mails, hex/0x literals, long digit-bearing tokens, base64/hash-shaped
  tokens, `\escape` sequences; camelCase/snake_case splitting with acronym
  handling (typos' key insight).
- **Corrections data = `typos-dict` crate** (MIT OR Apache-2.0, ~95k
  entries, compiled-in PHF map — zero startup cost). A tiny built-in
  allowlist (`ser`, `flate`, `referer`) covers words that are misspellings
  in prose but everyday identifiers in code. Never used: codespell/
  misspell/wordfreq data (CC BY-SA share-alike contamination).
- **Wordlists = FST sets** (`fst` crate): O(len) lookup, memory-light,
  and Levenshtein-automaton suggestions for free. Mutable word sources
  (project/global words) live in a hash set so editor add-word is instant
  without an FST rebuild.
- **Japanese without a morphological analyzer** (v0.1): katakana-run
  extraction + three check families:
  - *Consistency* (default): flag a katakana spelling only when the same
    document also uses its trailing-long-vowel twin — RedPen's trick,
    dictionary-free, near-zero noise. No style is imposed (JIS Z 8301:2019
    abolished the omit-ー rule).
  - *Style enforcement* (opt-in): curated pair table, `long`/`short`.
  - *Mechanical*: fullwidth alphanumerics, halfwidth katakana (with ﾞ/ﾟ
    merging), fullwidth space (code files only by default).
- **Registry = static files on GitHub Pages.** `index.json` (generated by
  `cargo xtask registry`) + plain text/TOML dictionaries, sha256-verified.
  `dict add` also wires the reference into `ayame-spell.toml` via
  `toml_edit` (formatting preserved), so a team shares dictionaries by
  committing one line. `$AYAME_SPELL_REGISTRY` swaps in private registries.
- **Bulk-first UX.** `words collect` (frequency-ranked), `words triage`
  (multi-select → project/global/ignore), VS Code "Review Flagged Words"
  (same flow over LSP executeCommand). This addresses the top complaint
  about every dictionary-mode checker.
- **No silent degradation.** Skipped binaries/oversized files are counted
  in the summary; the LSP logs when diagnostics are capped (1000/doc) and
  re-checks >4 MB docs on save instead of on type.

## Data provenance (all license-clean for MIT OR Apache-2.0)

| Data | Source | License |
|---|---|---|
| EN corrections (built-in) | typos-dict crate | MIT OR Apache-2.0 |
| en-base wordlist (registry) | SCOWL ≤ size 60 + abbreviations | SCOWL permissive |
| ja-variants (registry) | SudachiDict synonym dictionary, katakana notation-variant pairs (form=0, abbr=0, flag 2→0) | Apache-2.0 |
| ja-tech-variants, python/rust/web (registry) | hand-curated here | MIT OR Apache-2.0 |
| code-terms (built-in, dictionary mode only) | hand-curated here | MIT OR Apache-2.0 |

Rejected on license grounds: codespell dictionary & Wikipedia misspelling
lists (CC BY-SA), wordfreq data (CC BY-SA), SUBTLEX (non-commercial).

## Measured performance (v0.1, Ryzen-class desktop)

- 35 MB / 400k-line text file: **1.26 s wall, 56 MB peak RSS**, all 40
  seeded typos found (single file, so single-threaded).
- Repository scans parallelize across files via the `ignore` crate's
  parallel walker (gitignore-aware).

## Roadmap

- **v0.2 — suggestion ranking & levels**: frequency-ranked suggestions
  (SymSpell MIT frequency list), codespell-style graded correction levels
  (`clear`/`rare`/`informal`), `ayame-spell trace <word>` (which source
  allowed/flagged it and why).
- **v0.3 — prh compatibility**: read prh YAML rules (expected/pattern/
  specs/wordBoundary) to inherit the existing Japanese ruleset ecosystem;
  ですます/である consistency; ら抜き list; 送り仮名 pair tables from the
  内閣告示 (government notices are copyright-exempt).
- **v0.4 — morphology (opt-in)**: lindera + IPADIC behind a cargo feature
  (lindera is on crates.io and MIT; sudachi.rs is git-only so unusable as
  a dependency). Enables 誤変換 candidate detection via homophone
  confusion sets.
- **Distribution**: prebuilt binaries in GitHub Releases (workflow exists),
  VS Code Marketplace publishing with per-platform bundled servers,
  cargo-binstall metadata, Homebrew/AUR.
- **Editor breadth**: the LSP already works in Neovim/Helix/Zed; ship
  configs/docs for each.
